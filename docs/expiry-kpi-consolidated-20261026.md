## Root causes and correction

1. Every prior KPI click requested another server page and waited for it before updating selection. The supplied Preview had no double-click coordinator. Replaced its toggle-only handler with one gesture coordinator: immediate selected-state feedback, a single 350ms click/double-click decision window, and preserved pre-gesture selection for additive double-clicks. A double-click on an already selected month keeps it selected without duplicates. Keyboard activation is immediate. All Items and the existing X cancel pending gestures and clear only KPI selection. Reset All cancels any undecided gesture. Opening Filters/Export settles the gesture before taking its snapshot. Independent Search, Group, Operator and manual month constraints remain intact.
2. Added `kpiKeys` and the server month reference within the existing `filters` object. The canonical `ExpiryInventoryFilters.wire` serializes their date union intersected with independent constraints for table reads, exports and existing selection/mutation previews. No persistent selection store was added. A small matching helper is used only on complete authorized read projections.
3. The previous response held only the visible page, so it could not safely represent all inventory locally. An initial bounded read (maximum 250 rows) can seed an ephemeral projection **only when metadata count equals returned rows and IDs are unique**. It is scoped to pharmacy/user, auth identity epoch, permission generation, resolved state, sort and independent filters; maximum age 30 seconds. KPI changes and pagination reuse it without RPCs. Partial/stale/different scopes use the original authorized server query. Standard refresh bypasses it; existing mutation acknowledgements, pending correction replay and account reset invalidate it. It never grants permission or becomes a durable source of truth. Larger inventories do not get an unbounded download.
4. Added All Items using a bounded authorized query's full active count/units metadata. It includes dates beyond six months and does not recalculate from the chosen month subset. Existing seven exclusive date buckets and Asia/Riyadh summary reference are retained; rollover is server-driven. No additional polling loop.
5. Excel explicitly bypassed filters through its full-active flag. Removed that bypass. Excel, PDF and Print now all call the same `shelfRows` with the same canonical filter snapshot across all pages. Report columns, dates, identifiers, quantity values and workbook formatting code are unchanged. This supersedes the old full-active Excel contract.
6. Replaced the earlier monthly CSS block rather than append conflicting identity rules. Eight coordinated colors match date badges; normal top borders are 4px. Numeric typography stays **18px**, full thousands separators, with Records and Units on separate aligned lines. Shared intrinsic minimum widths grow for long totals and only the KPI strip scrolls when necessary. Approved green identities apply to distant Inventory months only. Darker text tones retain contrast while specified accents/backgrounds remain exact.
7. Whole-row pale blue hover/focus; existing floating-menu state and a stable dialog row ID retain context through menus/editing. Badge colors remain unchanged. No new editing or write mechanism.

## Measured responsiveness and limits

See `docs/evidence/expiry-kpi-consolidated/performance.json` for the final exact measurements. In the isolated 73-row Chromium fixture, cached KPI interactions issue **zero new RPCs**. Selected-state DOM feedback was below 1ms; a measured post-paint frame remained below 100ms. Additive filtering after the second click was approximately 6–8ms. Single-click table completion was approximately 360ms, including the documented 350ms gesture decision. The 200ms single-click total goal is therefore **not met**; correctness of distinguishing mouse gestures takes precedence. These are measurements on this execution host, not promises for Windows hardware or network-dependent partial inventories.

The complete-projection limit is 250 records/30 seconds. Bigger or incomplete datasets retain server-authoritative filtering and network latency. Full exports always use fresh server reads, not the projection. Live multi-PC timing, physical Chrome zoom and Product Owner visual/interaction acceptance remain untested.
