# PHARMFLOW CURRENT CHECKPOINT

Date: 23 August 2026
Version: Phase 2C.11.4.8 — Authoritative First Render
Status: READY FOR TEST

## 2C.11.4.7 TEST RESULT
FAILED: old finalized Order statistics still flashed briefly after Sign In.

## EXACT ROOT CAUSE
2C.11.4.7 corrected the cloud account-context path, but initial application
bootstrap still called initializeState() -> loadWorkspaceSnapshot() BEFORE
router/UI initialization.

That meant stale local receiving statistics/order data could enter AppState
before Supabase hydration and become the first visible render.

## ROOT FIX
- initializeState no longer loads Current Workspace from browser persistence.
- It starts with a deliberately empty runtime.
- startApplication now AWAITS restoreCloudWorkspaceOnLogin BEFORE startRouter
  and initializeUI.
- Same-tab re-authentication also hydrates server authority BEFORE refreshUI.
- Supabase Active Order Manifest / Cloud Workspace therefore determines the
  first authenticated render, not browser cache.

## DATA SAFETY
- No SQL.
- No Receiving quantity logic changes.
- No Finalize/Archive changes.
- No Expiry/GS1 changes.
- Local snapshot functions remain available for persistence; they are simply
  not allowed to outrank server authority during authenticated startup.
