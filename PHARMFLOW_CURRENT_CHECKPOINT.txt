# PHARMFLOW CURRENT CHECKPOINT

Date: 23 August 2026
Version: Phase 2C.11.4.7 — Server-First Login Hydration
Status: READY FOR TEST

## OBSERVED AFTER 2C.11.4.6
Finalize/manifest cleanup succeeded and finalized orders disappear correctly.
After Sign Out -> Sign In, old order numbers flashed for about one second and
then disappeared.

## BUG CLASSIFICATION
Local persistence hydration / UI first-render mismatch.
Not a server data-integrity regression.

## ROOT CAUSE
On authenticated context switch PharmFlow restored the account-scoped local
workspace snapshot and refreshed the UI BEFORE Supabase Active Order Manifest
and Cloud Workspace authority reconciled.

A stale browser snapshot could therefore render old/finalized Orders briefly.

## ROOT FIX
- Authenticated sign-in starts with an empty runtime workspace.
- Account-scoped local workspace is no longer allowed to be the first render.
- Active Order Manifest / Cloud Workspace remains authoritative.
- If BOTH server authorities say there is no active Order, the stale scoped
  local snapshot is deleted and replaced with an empty snapshot permanently.
- No SQL migration.
- No Receiving / Finalize / Archive / Expiry business logic changed.

## NON-REGRESSION
An actually active server Order must still hydrate after sign-in on PC2/PC3.
The fix prevents stale local-first display; it does not suppress cloud Orders.

## TEST
A. Empty workspace:
1. Sign Out.
2. Sign In.
3. Old/finalized order numbers must NOT flash.
4. Receiving remains empty after sync.

B. Active workspace later:
1. Upload an active order on PC1.
2. Sign in/reload on another PC.
3. The server active order must appear after hydration.
